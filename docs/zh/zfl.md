# zfl

`zfl` 是 ZFL (Zsh Function Library) 框架的内置命令行管理工具，用于提供函数自动发现、元数据查询、运行依赖检测等功能，帮助规范和探索可用的命令行脚本。

同时，ZFL 支持将本地个人函数与共享的社区函数进行隔离，并自动进行懒加载和自动补全代理注册。

---

## 📂 目录隔离机制

ZFL 支持以下两个目录下的函数：
1.  `functions/`：存放社区官方/通用的公共函数。
2.  `custom_functions/`：存放用户个人的私有脚本（此目录已被 `.gitignore` 忽略，升级框架时不会产生冲突）。

当 Zfl 启动时，会自动扫描上述两个目录下的所有 `.zsh` 脚本并为其注册懒加载桩和 Tab 补全代理。

---

## 📖 用法与子命令

```bash
zfl <子命令> [参数]
```

### 可用子命令

*   **`list` 或 `ls`**
    扫描 `functions/` 和 `custom_functions/` 下的所有物理文件（包含 `.zsh`、`.sh` 及无扩展名脚本），展示其函数名称、来源（社区/用户）及状态描述。当检测到非 `.zsh` 扩展名、缺少 `#?` 元数据注释或缺失主入口函数时，会在表格中红/黄高亮警示，并在尾部生成“**文件格式诊断报告 (Diagnostics Report)**”。
*   **`info <函数名>`**
    查看特定函数的详细元数据（如作者、版本、必要外部依赖、用法、使用示例等）。
*   **`check`**
    扫描所有函数声明的外部系统依赖，检查它们在当前系统中是否已安装，并给出检测状态。
*   **`lint [函数名...]`**
    对指定的函数文件（或不传参时对所有函数）进行代码静态质量与规范校验。包含扩展名 `.zsh` 校验、`#?` 头部元数据完整性、全局变量泄漏及 FD 3 安全等。
*   **`addfunc [函数名称]`**
    交互式在 `custom_functions/` 目录下生成包含全套规范 `#?` 元数据注释及多语言函数骨架的标准 `.zsh` 模版，并在当前 Shell 会话中即时声明懒加载桩函数与 Tab 补全代理。
*   **`remove <函数名>` 或 `rm <函数名>`**
    安全删除指定的函数文件（会提示确认 `[y/N]`），并在当前会话中卸载该函数与补全代理（`unfunction`），同时自动同步项目结构树。
*   **`help` 或 `-h`**
    显示帮助说明。

---

## 💡 示例

```bash
zfl list            # 列出所有可用函数及格式诊断
zfl addfunc my_tool # 交互式新建自定义函数模板
zfl info weather    # 查看 weather 工具的元数据
zfl check           # 校验所有函数的外部依赖状态
zfl lint weather    # 校验 weather 函数的代码规范与潜在泄漏风险
zfl lint            # 校验 functions/ 和 custom_functions/ 下的所有脚本
zfl remove weather  # 安全删除 weather 函数文件并清理当前终端的会话与结构树
```

## 🔍 代码静态质量校验 (zfl lint)

`zfl lint` 集成了 Python 编写的静态分析工具，用于在本地或 CI 流程中校验提交函数脚本的质量，核心校验项如下：

1.  **文件扩展名与映射**：文件名扩展名必须为 `.zsh`；文件 `foo.zsh` 内部必须且只能定义主入口函数 `foo()`。
2.  **头部元数据规范 (#?)**：校验文件头部是否显式写全规范的 `#?` 注释块全部 7 大基础字段（`name`、`description`、`author`、`version`、`deps`、`usage`、`example`），确保函数自描述文档完整。
3.  **全局变量泄漏隐患**：扫描函数体内赋值的变量，凡是未显式使用 `local`、`typeset` 声明，且不在系统全局白名单中的变量都会被发出泄漏警告。
4.  **FD 3 泄漏风险**：检测包含后台任务（如 `&`、`coproc`）的语句行是否伴有关闭文件描述符 3（`3<&-`）的操作，防止多终端异步拉起进程导致父 Shell 锁死。
5.  **硬编码颜色字符**：拦截写死 ANSI escape 转义色彩控制符的行，倡导使用框架提供的 `load_color`。
6.  **配套文档检测**：检查 `docs/` 下是否有同名的 `.md` 格式文档，鼓励健全的文档配套机制。

## 💡 ZLE (vared) 交互输入最佳实践

在编写包含 Shell 交互输入的脚本时，普通 `read` 命令由于不经过 Zsh Line Editor (ZLE)，在终端中使用中文输入法（全角 2 列字符）退格删除时容易因 CJK 宽字符光标列计算偏差产生显示残影。框架推荐使用 `vared` (Zsh Variable Editor) 来接管交互输入：

```zsh
# 使用 ZLE 官方行编辑器接管变量输入，100% 避免中文输入法退格显示残影
if [[ -t 0 && -t 1 ]]; then
    my_var=""
    vared -p "> " my_var
else
    read -r my_var
fi
```

## 📝 社区脚本元数据标准

为了能被 `zfl` 命令自动识别并正确呈现说明信息，所有放入 `functions/` 或 `custom_functions/` 的脚本推荐在**文件头部**包含以下格式的元数据注释（以 `#?` 开头）：

```zsh
#? 名称: weather
#? 描述: 终端快速查询实时天气与天气预报
#? 作者: Royi
#? 版本: 1.0.0
#? 静默: true
#? 依赖: curl
#? 用法: weather [城市名称]
#? 示例: weather beijing
```

> **🔇 首次懒加载提示控制机制**:
> 1. **脚本元数据标记**：在脚本头部添加 `#? quiet: true`（或 `#? 静默: true`、`#? lazy_quiet: true`），该函数首次被调用执行懒加载时将不再输出 `[lazy_load] for <函数名> ...`。
> 2. **全局环境变量**：设置 `export ZFL_LAZY_QUIET=1` 可全局静默所有函数的首次懒加载提示。
> 3. **单函数临时环境变量**：使用 `ZFL_LAZY_QUIET_<func_name>=1` 或 `0` 可单次精准覆盖控制（优先级最高）。
> 4. **终端启动任务联动**：在 `core/startup_tasks.zsh` 运行期间默认静默懒加载提示，避免污染启动流输出。

*元数据解析器在读取到非注释行或空行后将自动停止，保证极其轻量的高效执行。*

## 🛡️ 依赖声明助手 (`zfl_require`)

在编写需要特定第三方命令行工具（如 `fzf`、`jq` 等）的函数时，推荐在函数入口处调用框架的 `zfl_require` 进行依赖断言。

### 示例

```zsh
my_tool() {
    # 声明并校验依赖，若缺失将输出红色的友好提示并返回 1
    zfl_require fzf jq || return 1

    # 实际业务逻辑
    ...
}
```
